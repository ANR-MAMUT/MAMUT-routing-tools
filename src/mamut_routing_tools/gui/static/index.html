Manual

Depot position
Which road intersection becomes node 1, the depot.
Centered
Closest vertex to the mean of all vertices — short, balanced routes.
Random
A uniformly drawn vertex, so difficulty varies with the seed.
Excentered
Closest vertex to the south-west corner — long approach legs.

POI categories
Choose amenity types

City fetches store every listed category. These checks only filter which POIs generation may select.

POI attachment
How an amenity binds to the road graph, which decides how many of them can be customers at all.
Strict
The POI's nearest road node must itself be a graph intersection. Matches the published Julia pipeline exactly, and discards most of a city: an amenity whose closest node sits mid-segment is dropped even when a real intersection stands a metre further.
Snap
The POI moves to the closest intersection within the radius below, the way hand-picked POIs have always worked. Far more of the extract becomes usable; each customer records how far its amenity moved.

Click a marker to pick or unpick it; shift-click sets it as the depot. Names come from OpenStreetMap where available. Picks are snapped to the nearest road intersection, so two POIs on the same corner collapse into one customer.

Target proportion before availability fallback; missing POI customers are filled parametrically.

The pool radius is the exponential decay distance: cluster attraction halves at this distance.

Demand type
The distribution the per-customer demand is drawn from. Type 6 is spatially correlated (heavy customers cluster on one diagonal), type 7 mixes a few bulky customers into many small ones.
Route size band
The target number of customers per route. A value r is drawn uniformly from the band and sets the vehicle capacity, which in turn gives the fleet size (ceil(total demand / capacity)). It is a target, not a hard route count.
